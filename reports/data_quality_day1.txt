==================================================
ANOMALIES & OBSERVATIONS
==================================================

1. AMFI Code Data Type
The amfi_code column is stored as int64 in multiple datasets. While this works for identifying funds, AMFI codes are identifiers rather than numerical values. Converting them to string during preprocessing will ensure consistent handling and prevent issues during joins or future transformations.

2. Date Columns Stored as Strings
The launch_date, date, transaction_date, and portfolio_date columns are currently stored as string (str/object) data types. These columns should be converted to datetime format during the data cleaning phase to enable proper filtering, sorting, and time-series analysis.

3. Missing Values in yoy_growth_pct
The yoy_growth_pct column in 04_monthly_sip_inflows.csv contains 12 missing values. This is expected because Year-over-Year growth requires data from the previous year, and the dataset begins in January 2022. Therefore, the first twelve months cannot have valid YoY values.

4. Different Date Formats
The live NAV data downloaded from the API uses the DD-MM-YYYY date format, whereas the provided datasets use the YYYY-MM-DD format. These different formats must be standardized before combining or merging the datasets to avoid incorrect date matching.

5. Quarterly Folio Count Data
The 06_industry_folio_count.csv dataset contains records at quarterly intervals rather than monthly intervals. Extra care will be required when merging this dataset with monthly datasets to avoid introducing inaccurate or duplicated values.
